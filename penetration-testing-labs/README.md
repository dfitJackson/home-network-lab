## Overview

This directory represents my **penetration testing portfolio**, combining:

- **Home lab–based security testing projects** used for skill development and experimentation
- **Real-world, contract-based penetration testing experience**, documented in a sanitized and ethical manner

The goal of this repository is to demonstrate:
- How I approach security testing
- How I document findings
- How I distinguish learning environments from professional engagements
- How I validate issues rather than relying on automated output alone

---

## Repository Structure & Intent

This repository intentionally contains **two types of work**:

### 🔬 Lab-Based Projects
These are controlled, non-production environments used to:
- Learn tools and techniques
- Practice enumeration and exploitation
- Document step-by-step testing workflows

Lab projects are **clearly labeled** and do not represent live client systems.

### 🏢 Real-World Experience (Sanitized)
I have performed **paid, contract-based penetration testing work** under defined scope and confidentiality constraints.

As a result:
- Client names, URLs, and raw evidence are not published
- Findings are summarized at a high level
- Equivalent lab-based demonstrations are used where possible

This mirrors how professional consultants balance transparency with ethics.

Recent professional work includes:

## Methodology & Approach

Across both labs and real-world work, my approach emphasizes:
- Validation over volume
- Manual testing supported by automation
- Clear scoping and non-intrusive techniques unless authorized
- Reproducible evidence and false-positive elimination

Methodologies align with OWASP Web Security Testing Guide (WSTG) principles and real consulting practices.

## Ethics & Disclosure
